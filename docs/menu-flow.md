# 첫 화면·게스트·모드 진입 흐름 — 2026-11-06

## 변경 전후

이전에는 첫 화면부터 전체 Babylon 게임 Scene을 만들고, 점수·슛 HUD와 온라인 Room 폼,
시나리오 선택·재시도·음량·음소거·오디오 활성화·카메라 흔들림을 함께 보여줬다.

현재는 `HOME → FRIENDS / PRACTICE_SELECT → CONNECTING / PLAYING → HOME`으로 구분한다.
HOME에는 로고·한국어 소개·게스트 닉네임·친구와 플레이·혼자 연습·작은 설정/안내/크레딧만 있다.
상세 설정 분리는 이번 작업에서 완료했다. Scene 분리를 크게 늘리지 않기 위해 코트 선을
표현한 정적 SVG/CSS 배경을 사용했다. 배경용 엔진·시뮬레이션·캐릭터·공·Room은 없다.
Babylon 모듈은 미리 불러올 수 있지만 Engine/Scene/AudioManager는 모드 진입 후에만 만든다.

친구 화면에는 기존 1대1/자유 연습 모드, 방 생성, Room ID 참가와 뒤로가기를 배치한다.
존재하지 않는 방 참가를 방 생성으로 대체하지 않는다. 연결 중 버튼은 잠그고,
취소·설정 이동·첫 화면 이탈로 무효화된 연결이 늦게 성공하면 Room을 닫는다.
방 생성/참가 후 읽기 전용 초대 코드와 복사 버튼을 제공하며 Clipboard 실패 시
코드를 선택해 수동 복사할 수 있다. 준비·경기·결과·재경기는 기존 MatchPanel을 사용한다.

연습 화면에는 기존 7개 시나리오 설명과 시작 버튼을 배치한다. 연습 중 Esc 메뉴에서
재시도/시나리오 변경을 할 수 있다. 같은 Scene을 유지하며 기존 scenario/reset API를 호출한다.
모든 나가기 버튼은 첫 화면으로 돌아간다. 온라인 퇴장·중단 판정은 기존 서버 정책이다.

## 닉네임과 설정

- 닉네임: `check-the-ball.nickname.v1`. 기존 유효한 저장 이름을 복원하고 없으면 `게스트####`를 제안한다.
  앞뒤 공백 제거, 빈 이름·제어 문자·20자 초과를 거부한다. 입력 blur/모드 진입 때 유효한 이름을 저장한다.
  길이는 기존 서버와 같이 JS 문자열 길이(UTF-16) 기준이다. 한글/HTML 모양 이름도 일반 텍스트로만 렌더링한다.
- 서버 Room 인증에서도 같은 `packages/protocol/src/nickname.ts` 검증을 사용한다.
  중복 표시 이름은 허용하며 실제 식별은 기존 session ID다. 참가 중 이름 수정은 제공하지 않는다.
- 오디오: 기존 `check-the-ball.audio.v1` 키와 volume/muted 형식을 유지한다.
- 카메라 흔들림: `check-the-ball.camera-motion.v1`의 true/false 문자열. 기존에 저장 키가 없어서 새 키를 추가했다.
- localStorage 읽기는 effect에서만 수행한다. 저장소 접근/저장이 실패해도 현재 React 메모리 상태로 플레이한다.
- 첫 화면과 게임 메뉴가 같은 설정 상태를 사용하고, 실행 중이면 기존 runtime의 setAudio/setCameraMotion에 반영한다.
  설정 화면을 위해 별도 AudioManager를 생성하지 않는다.

설정은 음량·음소거·카메라 흔들림만 표시한다. 조작 안내와 크레딧은 별도 페이지형 패널이다.
음원 파일·출처·라이선스를 바꾸거나 삭제하지 않았고 기존 attribution 링크를 크레딧에서 제공한다.
시작/계속하기 클릭에서 기존 오디오 unlock과 Pointer Lock을 요청한다. 잠금 실패 시 클릭해 다시
시작할 수 있는 메뉴를 유지한다. 오디오 unlock이 실제로 실패한 경우에만 복구 버튼을 표시하며
음소거/음량 0 상태는 실패로 표시하지 않는다.

## 수명과 입력

Scene 생성은 명시적인 연습 시작 또는 유효한 온라인 연결 성공 시 한 번 수행한다.
설정/안내/메뉴 이동은 Scene을 다시 만들지 않는다. 생성 함수가 준비되기 전에는 시작 버튼을 잠근다.
연습 시작은 준비된 생성 함수를 사용자 클릭에서 동기 호출해 오디오/Pointer Lock 제스처를 보존한다.
온라인 연결 성공은 비동기이므로 경기/코트 입장 클릭을 별도로 받는다.

첫 화면 복귀는 연결 시도 세대 무효화 → runtime.dispose → OnlineSession.close → HUD/실행 상태 제거로 처리한다.
runtime.dispose는 기존 엔진/Scene/렌더 루프/네트워크 입력 타이머/이벤트/오디오를 정리한다.
비동기 Scene 로딩/오디오/Pointer Lock 콜백은 세대를 확인해 이미 나간 화면에 상태를 쓰지 않는다.
Strict Mode의 effect에서 게임을 자동 생성하거나 자동 참가하지 않는다.

메뉴 진입은 기존 clear/cancel을 재사용하는 runtime.pause로 입력을 중립화하고 Pointer Lock을 해제한다.
입력창/선택 필드의 키는 게임 window 리스너까지 전달하지 않는다. Esc는 설정/안내에서 뒤로가기에 사용할 수 있다.
메뉴는 모달이 아닌 전체 페이지형 패널이며 제목으로 포커스를 이동한다. Tab/포커스 테두리와 내부 스크롤을 제공한다.
온라인은 메뉴에서도 기존 서버/수신 루프를 유지한다. 경기 규칙·공 물리·충돌·캐릭터 모션·예측/보정 계산은 변경하지 않았다.

## 확인 방법과 제한

1. 새로고침 후 닉네임과 두 시작 버튼만 보이는지 확인한다. 자동 마우스 잠금과 점수 HUD가 없어야 한다.
2. 이름을 수정하고 다른 곳을 클릭한 후 새로고침해 복원을 확인한다. 빈 이름은 모드 진입을 막아야 한다.
3. 설정에서 음량·음소거·카메라 흔들림을 바꾼 뒤 연습/첫 화면/새로고침을 거쳐 값을 확인한다.
4. 친구와 플레이에서 방을 만들고 코드를 복사해 다른 브라우저에서 참가한다. 틀린 ID/가득 찬 방 오류 후 수정한다.
5. 연결 중 뒤로/설정/첫 화면으로 나간 뒤 늦은 연결이 플레이 화면을 열지 않는지 확인한다.
6. 연습 시작·Esc·재시도·설정·복귀·다른 연습 시작을 반복한다. 온라인 Esc는 상대 경기를 멈추지 않아야 한다.
7. 기존 1대1 준비·시작·결과·상호 재경기와 경기 중 퇴장 중단을 확인한다.

검증 실행 결과는 아래에 기록한다. 배포·외부 장치·수동 음질/플레이 체감·모바일 게임 조작은 별도 범위다.
모바일 조작은 이번에 추가하지 않았고 메뉴에서 데스크톱 입력이 필요함을 안내한다.

## 후속 작업

- 첫 화면의 상세 설정·시나리오·재시도·출처 분리는 이번에 완료했다.
- 향후 작은 온라인 광장을 첫 화면 배경과 연결한다. 광장은 매칭/방 참가의 필수 이동 경로가 아니다.
- 빠른 매칭, 로그인, 친구 목록은 별도 단계다. 현재 작동하는 것처럼 버튼을 만들지 않았다.
- 향후 2대2/3대3/4대4를 확장할 예정이다. 현재 인원 제한과 1대1 경기 정책은 변경하지 않았다.

## 주요 변경 파일

`Game.tsx`는 메뉴·실행 수명, `GameHud.tsx`는 기존 플레이 HUD, `MenuPanels.tsx`는 설정/안내/크레딧,
`RoomInvite.tsx`는 초대 코드/복사를 담당한다. `menuState.ts`는 저장·입력 검증·연결 세대와 오류 안내,
`nickname.ts`와 서버 인증은 표시 이름 검증을 담당한다. `createGame.ts`는 메뉴 pause와 오디오 실패 표시,
`onlineClient.ts`는 종료 시 leave 실패 처리만 보완했다. 경기/물리 규칙 파일은 수정하지 않았다.
