# 2대2 연습 기반

정식 경기가 아닌 하나의 코트/공을 공유하는 자유 연습이다. `practice2v2` 방은 최대 4명,
팀 A/B 각각 최대 2명이며 1~3명이어도 바로 연습할 수 있다. 기존 `practice`는 2명,
`duel`은 2명과 기존 준비·11점·결과·재경기를 유지한다. 방 생성 이후 모드/정원은 바꾸지 않는다.

## 확인한 2인 가정과 변경 범위

| 기존 가정 | 이번 처리 |
| --- | --- |
| Room/core 정원 2명, slot 0/1 | 새 모드만 4명, 빈 slot 0~3 재사용 |
| 스폰 x=-1/+1 두 곳 | 새 모드의 팀별 후보 + 실제 점유 검사 |
| `movePair`가 두 위치만 반환 | 3~4명만 `moveGroup`; 1~2명 경로 보존 |
| 예측 충돌 상대 한 명 | 최신 서버 좌표의 모든 원격 실린더를 보수적인 프록시로 사용 |
| 단일 opponent와 라벨·드리블음 | ID별 원격 rig/label/view 캐시와 원격 전원 오디오 순회 |
| 2칸 점수판 | 새 모드만 A/B 명단 + 개인 기록 표시; 팀 합계 없음 |
| 준비/공격권/재경기 2명 | duel 전용으로 유지, 일반화하지 않음 |

캐릭터 외형/골격, 이동 속도, 점프, 공 물리, 슛/패스 계산, 틱/전송률, 채팅 규약을 변경하지 않는다.
npm 및 package-lock.json과 설치된 Colyseus 버전을 유지하며 추가 패키지는 없다.

## 팀과 서버 검증

- `teams.ts`: 팀 ID는 A/B. 자동 배정은 인원이 적은 팀, 동수면 A 우선이다.
- 방 생성/코드 참가/목록 참가 전에 희망 팀을 선택할 수 있다. 자동 배정이 기본이다.
  명시한 팀이 가득 차면 다른 팀으로 몰래 바꾸지 않고 참가를 거절한다.
- `onAuth`는 선택값/현재 정원을 확인하고, 실제 `world.join`에서 다시 확인한다.
  팀 정원 검사와 배정 사이에 await가 없으므로 예약 접속이 동시에 완료되어도 최대 2명을 넘지 않는다.
- 방 안 `teamChange`는 해당 연결의 sessionId에만 적용한다. 요청 payload는 팀 ID 하나다.
  서버가 확정한 스냅샷만 실제 팀으로 표시한다. `teamError`/`teamChanged`는 요청자에게만 보낸다.
- 같은 팀은 no-op. 성공한 변경 사이 750ms 대기, 연결별 5초 6회 요청 상한이며 퇴장 시 삭제한다.
- 공개 목록은 기존 조회 API를 유지하며 새 모드의 1~3/4 인원과 모드를 반환한다.
  비공개/예약 포함 만석은 제외하며 실제 참가 검증을 대신하지 않는다.
- A는 기존 blue, B는 orange 팔레트를 사용하고 라벨에 [A]/[B]와 YOU를 표시한다.
  팀 팔레트는 이 모드에만 표시하고 저장된 개인 색상은 바꾸지 않는다.

## 안전 위치와 불연속 처리

- 후보: A의 x=-2.1/-3.6, B의 x=2.1/3.6, z=-1.8/1.2/-4m.
  `BODY.radius`와 실제 점유 실린더(스크린 포함), 코트 경계로 검사한다.
- 후보가 차면 반경 기반 간격의 유한 격자를 찾는다. 자리 없으면 NO_SAFE_SPAWN으로 거절하며 다른 사람을 밀지 않는다.
- 팀 변경 시 이동 큐와 행동/충전/Gather/예약 발사/수비/스크린을 정리한다.
  수신 완료 입력은 기존 ACK frontier까지 retire하며 seq를 0으로 되돌리지 않는다.
- 소유 공은 이전 월드 위치에서 자유 공으로 해제하고 속도만 0으로 한다. 이미 날아가는 공은 유지한다.
- actor의 `relocationEpoch`를 증가시킨다. 일시적인 lastPositionWriter 문자열이 다음 틱에
  바뀌어도 재배치를 놓치지 않는다. 로컬은 미확인 재생·시각 오프셋·입력 상태를 비우고,
  상대는 해당 두 스냅샷 사이 위치를 보간하지 않는다. 내 yaw/pitch는 서버 시선으로 덮어쓰지 않는다.

## 몸 충돌과 공 행동

`bodies.ts/moveGroup`은 전원 사이 상대 이동의 최초 swept-circle 접촉과 코트 경계를 함께 구한다.
스크린은 기존 3개 실린더를 사용한다. 접촉까지 이동하고 각자의 안쪽 법선 성분만 제거해 접선 이동을 허용한다.
멈춘 캐릭터에 이동량을 전달하지 않는다. 점프 높이와 관계없이 수평 배타 영역을 유지한다.
최대 BODY.iterations=8회, 동시 접촉은 참가자 수만큼 반복 투영하며 미해결 잔여 이동은 버린다.
초기 겹침은 최대 BODY.recoveryIterations=16회 복구하고, 실패하면 전원 검증된 안전 격자에 배치한다.
최종 위치 집합이 부적합하면 검증된 시작 집합으로 되돌려 관통보다 이동 제한을 우선한다.
기존 반경 0.42m, 허용 오차 1e-6m, skin 1e-5m를 유지한다.
3~4명 처리 순서를 틱마다 순환하며 캐치·블록·스틸 후보도 slot 정렬 후 시작점을 순환한다.
2인 상대 이동 경로는 기존 알고리즘 그대로다. 최신 원격 위치를 쓰는 보수적인 클라이언트 프록시와
실제 서버의 동적 충돌은 차이가 있어 접촉 시 위치 보정이 발생할 수 있다.

공은 Room당 하나다. 기존 슛/패스/회수/스틸/블록을 모두 ID 기반 소유권으로 유지한다.
이번에는 팀별 패스 조준, 아군 스틸/블록 면제, 팀 점수, 승패, 골텐딩, 파울을 넣지 않는다.
따라서 같은 팀의 공도 기존 규칙으로 스틸/블록/캐치할 수 있다.
아웃 시 마지막 터치자 외 후보를 순환 순서로 선택하는 기존 개인 정책이며 팀별 공격권 규칙은 아니다.
퇴장 시 보유 공만 안전 해제하고 비행 공은 유지한다. 남은 인원은 계속 연습한다.

## 화면과 정리

첫 화면 → 온라인 플레이 → 방 만들기 → 2대2 연습. 코드로 참가/공개 목록 동선은 유지한다.
방 안 Esc 또는 `내 팀 · 팀 선택`에서 팀 패널을 연다. 기존 pause/cancel/Pointer Lock 해제 경로를
사용하므로 패널 중 게임 입력이 중립화되며 다른 사람의 연습은 계속된다. 새 단축키는 없다.
원격 캐릭터/라벨은 player ID별로 한 번 만들고 보간된 pose로 업데이트한다.
퇴장한 캐릭터의 라벨·뼈대·root만 제거한다. 스키닝 공유 재질은 유지하고 legacy의 소유 재질만 해제한다.
Scene 해제 시 전체 캐시와 구독을 정리하며 BGM 인스턴스를 새로 만들지 않는다.

## Windows 실행과 수동 확인

```powershell
npm.cmd run dev:online
```

기존 `apps/web/.env.local`의 NEXT_PUBLIC_GAME_SERVER_URL과 게임 서버의 GAME_WEB_ORIGINS 설정을 사용한다.
웹 브라우저/독립 프로필 네 개에서 서로 다른 닉네임으로 같은 Room ID에 참가한다.
1. 팀 선택 없이 A/B/A/B 배정을 확인하고 다섯 번째 참가가 거절되는지 확인한다.
2. Esc 팀 패널에서 팀 이동, 만석 버튼, 내 표시와 이름 위 [A]/[B], 개인 색상 복원을 확인한다.
3. 각자 이동/점프하며 중앙으로 모이고, 스크린과 코트 경계에서 겹치지 않는지 확인한다.
4. 공을 들고 충전하다 팀 이동 시 공이 이전 자리에 남고 늦은 발사가 없는지 확인한다.
5. 패스/캐치/스틸/블록/슛, 채팅 중 입력 차단, 한 명 퇴장 후 표시 제거와 자리 재사용을 확인한다.
6. 별도 1대1 방에서 준비/경기/재경기, 오프라인 연습의 기존 동작을 확인한다.

자동 확인:
```powershell
npm.cmd test
npm.cmd run test:server
npm.cmd run typecheck
npm.cmd run build
node --import tsx scripts/probe-teams-browser.mjs
```

실행 결과: 기본 테스트 248개, 서버 테스트 12개 통과. 웹/서버 타입 검사 및 프로덕션 빌드 통과.
브라우저 probe는 esbuild로 실제 Game 소스를 묶은 로컬 화면과 실제 서버를 사용한다.
Chrome 두 창에서 생성/참가/팀 변경, 원격 rig·닉네임 라벨 생성 및 퇴장 제거, 목록 복귀를 확인했다.
스크린샷/녹화는 없다. 서버 SDK 4인 통합 테스트와 실제 브라우저 4인 플레이는 다르며,
실제 네 창 이동/공 행동과 Next 배포 환경, 체감 성능은 미검증이다. 외부 배포하지 않았다.
