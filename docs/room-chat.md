# 머리 위 이름표와 Room 채팅

## 표시

`apps/web/game/createNameplate.ts`가 기존 더미의 DynamicTexture + billboard plane
방식을 재사용한다. 오프라인 이름은 기존 `PASS PARTNER`, 온라인은 서버 actor의
닉네임을 사용하며 로컬 1인칭 이름표는 만들지 않는다. 캐릭터 관절이나 머리 메시가
아닌 렌더 root + 높이를 기준으로 한다. 상대의 기존 보간된 root를 사용하므로 별도
네트워크 보간이나 게임 좌표 변경이 없다. 더미의 고정 스크린 배치도 같은 기준이다.

표시 설정 `NAMEPLATE`: root 위 2.12m, 최대 24m, 화면 폭 최대 160 CSS px.
배경 박스 없이 글자만 표시하며, 512×96 투명 텍스처는 이름 변경 때만 다시 그린다. 긴 이름은 표시만 말줄임하고 원래
문자열은 서버 데이터와 mesh metadata에 보존한다. 카메라 뒤/화면 밖/거리 밖은 숨긴다.
백보드·지지대·기둥·건물·펜스 등 생성 시 지정한 장애물만 100ms 간격으로 ray 검사한다.
바닥·캐릭터·공·이름표 자체는 대상이 아니다. ray는 각 메시의 로컬 좌표로 변환한다.
깊이 버퍼도 적용된다. 이름표 전용 텍스처/재질은 Scene 해제 시 함께 정리하고
캐릭터의 공유 재질은 건드리지 않는다. 상대 퇴장 시 이름표를 숨기고 재참가 시 재사용한다.

## Room 메시지 규약

공통 검증은 `packages/protocol/src/chat.ts`, 서버 기록은 `roomChat.ts`, 클라이언트
구독/확인 처리는 `roomChatClient.ts`에 둔다. 게임 입력 큐나 물리 tick/ACK는 변경하지 않는다.

| 채널 | 방향 | 내용 |
| --- | --- | --- |
| `chatSend` | 클라이언트 → Room | `body`, `clientMessageId` |
| `chatMessage` | Room → 같은 Room | `messageId`, `senderId`, `senderNickname`, `sentAt`, 검증된 `body`, `clientMessageId` |
| `chatError` | Room → 해당 발신자 | `clientMessageId` (식별 가능한 경우), `error` |
| `chatHistoryRequest` | 구독 완료 후 → Room | 최근 기록 요청 |
| `chatHistory` | Room → 요청한 참가자 | 최근 메시지 배열 |

발신자와 닉네임은 해당 연결의 서버 actor에서, 시각은 서버 Date.now에서 확정한다.
클라이언트가 보낸 위조 ID/닉네임/시간은 사용하지 않는다. 문자열만 허용하고, 양끝 공백을
제거하며 줄바꿈/탭은 공백으로 바꾼다. 나머지 C0/C1 제어 문자는 거부한다.
클라이언트와 서버 모두 정규화 후 Unicode 코드 포인트 200자, 요청 JSON UTF-8 1200 bytes
제한을 적용한다. 기존 WebSocket maxPayload 4096 bytes도 유지한다.

사용자별 5초 안에 확정 메시지 최대 3개. 초과 오류는 해당 사용자에게만 보낸다.
중복 ID는 기존 확정 메시지만 발신자에게 다시 확인하고 전체 방송/개수 차감을 반복하지 않는다.
중복 자료는 사용자당 최대 32개/60초, 전송 시 만료 제거. 퇴장하면 제한/중복 자료를 삭제한다.
기록은 Room 메모리의 최근 30개뿐이며 재경기에도 유지, Room 폐기 시 삭제한다.
기록 요청도 사용자당 500ms 간격으로 제한한다. DB·파일 저장이나 메시지 원문 로그는 없다.
웹과 게임 서버를 함께 갱신해야 새 채팅 채널을 사용할 수 있다.

클라이언트는 확정 메시지만 표시하며 `messageId`로 기록/실시간 메시지를 병합하고 최근 30개만
보관한다. 서버 확인을 기다리는 전송은 한 개, 확인 제한시간은 5초다. 실패/시간 초과 시
입력 내용을 지우지 않고 같은 본문 재전송에는 같은 clientMessageId를 사용한다.
Room 이탈 시 타이머·메시지 구독·기록·재시도 ID를 정리하며 늦은 수신은 무시한다.
다른 Room 메시지는 Room broadcast 범위 밖으로 전달하지 않는다.

## UI와 입력

Room 입장 후 왼쪽 아래에 최근 5개를 표시하고 8초 후 흐리게 한다. 입력 중에는 최근 30개를
스크롤할 수 있으며, 바닥 근처를 보고 있을 때만 새 메시지를 따라간다. JSX 일반 텍스트만
사용하고 링크/HTML/Markdown을 해석하지 않는다. 별도 useSyncExternalStore 구독으로 채팅
수신이 Game 전체 상태를 갱신하지 않는다. 화면 낭독기 알림은 새 실시간 메시지만 사용한다.

게임 조작 중 Enter 또는 채팅 버튼으로 연다. 다른 입력/설정/모달의 Enter는 빼앗지 않는다.
기존 `pause('CHAT')` → cancel과 Pointer Lock 해제로 키/버튼/충전을 중립화한다.
새 cancel 프로토콜은 없다. 입력 중 게임 키 이벤트를 막고 서버 경기는 계속 진행한다.
한글 조합 상태/KeyboardEvent.isComposing/229를 확인하고 Enter 반복 전송도 막는다.
Enter는 유효 메시지를 전송하고 즉시 플레이 복귀를 요청한다. 빈 입력 Enter/Esc 또는 코트 클릭도 채팅을 닫고 복귀한다. 입력창/기록을 클릭하면 편집을 유지한다.
작성 중인 내용은 해당 채팅 컴포넌트에서 보존한다. 설정/홈으로 나가면 초안은 지운다.
별도 ‘클릭해서 계속’ 버튼은 없다. Enter/코트 클릭 사용자 조작 안에서 기존 start/Pointer Lock 요청을 즉시 실행하며 서버 확인을 기다리지 않는다. 브라우저가 잠금을 거부하면 기존 게임 메뉴와 오류 안내를 사용한다. 서버 확인 실패 시 초안은 남기고 오류를 표시한다. 대기/종료 상태는 해당 경기 패널로 돌아간다.
클릭 자체가 공격 입력으로 전달되지 않으며 이전에 눌린 버튼의 mouseup도 발사하지 않는다.

## 검증

- `npm.cmd test`: 기존 게임/입력 회귀 + 검증·도배·기록·확인 제한시간·구독 정리 테스트.
- `npm.cmd run test:server`: 실제 SDK 참가자들의 동일/별도 Room, 위조 무효, 제한 오류,
  중복 확인, 재참가 기록 수신을 검사한다.
- `npm.cmd run typecheck`, `npm.cmd run build`.
- `node --import tsx scripts/probe-chat.mjs`: 실제 Game 컴포넌트를 임시 esbuild production
  번들로 실행한다. 별도 로컬 서버와 Chrome 두 창만 사용하며 스크린샷을 찍지 않는다.
  흐름 1은 이름표·가림·점프와 충전 → 채팅 → IME/전송 → 복귀/새 슛,
  흐름 2는 퇴장 → 같은 Room 재참가 → 기록/실시간 한 번 수신 → 홈 정리다.
  가림 재현에는 로컬 표시용 백보드 위치/크기만 잠시 바꾸고 복원한다.

브라우저 검증은 DOM/Scene 상태와 실제 로컬 Room 입력을 확인한다. 실제 한국어 IME 프로그램의
후보창 조작은 합성 composition 이벤트로 대체했다. 스크린리더 실제 청취, 다양한 OS/모바일,
배포 서버 지연/장시간 부하, 모든 화면 크기의 외형은 별도 수동 확인 대상이다.
이름표는 현재 지정된 고정 장애물을 대상으로 하므로 앞으로 벽을 추가할 때 대상 목록에 포함해야 한다.
