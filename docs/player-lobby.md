# PLAYER LOBBY — 정적 캐릭터 로비

중앙 카드 대신 왼쪽 메뉴 38% / 오른쪽 코트·캐릭터를 배치했다. 짙은 청록색·아이보리,
밝은 주황색 빠른 플레이·주황색 선택 표시를 사용한다. 주요 버튼은 20~24px, 본문은 16px 기준이다.
헤더에서 게스트 닉네임을 편집하며 기존 검증/저장 키, 설정·안내·크레딧·BGM 수명은 유지한다.

## 기능 연결

| 조작 | 실제 동작 |
| --- | --- |
| 1대1 / 2대2 | 기존 duel / teamDuel 선택. 주황색과 aria-pressed로 표시 |
| 2대2 빠른 플레이 | 기존 서버 예약/생성/참가/취소 경로 |
| 1대1 빠른 플레이 | 선택한 모드의 공개 대기 방에 자동 참가. 없으면 같은 모드로 생성 |
| 방 찾기 | 선택 모드 목록. 필터에서 모든 방/연습도 선택 가능 |
| 방 만들기 | 선택 모드를 기본값으로 기존 생성 화면. 연습 방 생성도 유지 |
| 코드로 참가 | 기존 정확한 Room ID 참가와 오류 복구 |
| 혼자 연습 | 기존 시나리오 선택 후 실제 연습 시작 |

첫 화면 복귀 시 연습 방 모드 선택을 대응하는 1대1/2대2 선택으로 정리한다.
빠른 플레이 취소/실패는 로비로 돌아오며 늦은 연결은 기존 세대 검사로 leave한다.
목록 조회만으로 예약/입장이 발생하지 않는다. 서버·공·경기·예측 규칙은 변경하지 않았다.

## 변경 파일과 에셋

- `app/PlayerLobby.tsx`: HTML 메뉴 및 별도 `LobbyBackdrop` 배경/캐릭터 영역.
- `app/playerLobby.css`: 로비 전용 반응형 스타일. 실제 플레이 HUD는 기존 스타일 유지.
- `app/Game.tsx`: 기존 액션/프로필 연결. 플레이 전 Engine/Scene/Room 생성 없음.
- `app/OnlineMenu.tsx`: 현재 선택 모드의 방 목록 필터. 기존 모든 방 조회 접근 유지.
- `public/assets/lobby/sunset-court.webp`: 1회 생성한 글자 없는 배경.
- `public/assets/lobby/player-*.webp`: 현재 모델의 색상별 투명 이미지 6종. 비율/머리/어깨/신발 재설계 없음.
- `public/assets/lobby/ATTRIBUTIONS.md`: 출처·최종 프롬프트·변환 방법.
- `scripts/render-lobby-assets.mjs`: 게임 모델의 정적 에셋 출력. 홈페이지에서 import하지 않는다.
- `scripts/probe-player-lobby.mjs`: 핵심 브라우저 흐름 확인, 스크린샷 없음.

선택 색상 이미지 하나를 표시하고 CSS로 바닥 그림자를 준다. 현재 모델의 면 분할/관절 외형 한계도 그대로다.
캐릭터 영역만 향후 3D로 교체할 수 있으나 이번에는 별도 첫 화면 렌더링 시스템과 온라인 광장을 만들지 않았다.
760px 이하에서는 메뉴를 우선하고 캐릭터를 아래 보조 영역으로 줄인다. 낮은 데스크톱 화면은 메뉴 내부 스크롤을 사용한다.
모바일 게임 조작은 추가하지 않았다.

## 실행과 검증

Windows: `npm.cmd run dev:online`.
웹 타입 검사, 메뉴/닉네임/설정 저장/BGM 관련 테스트 8개, 웹 프로덕션 빌드 통과.
`node --import tsx scripts/probe-player-lobby.mjs`는 실제 Game 소스를 묶은 로컬 브라우저에서 다음을 확인했다.

- 첫 화면 Engine/Room/WebSocket 0, 메뉴 폭 약 38%, 이미지 로드
- 닉네임·색상 저장/반영, 1대1 목록·선택 모드 생성 화면, 잘못된 코드 오류
- 390px 화면의 가로 넘침 없음, 낮은 560px 화면에서 버튼 접근
- 연습 시작 시 Engine 생성, 첫 화면 복귀 시 해제
- 지연된 2대2 요청 취소 후 늦은 연결 정리와 게임 자동 진입 방지
- 브라우저 예외 0, UI 스크린샷/녹화 0

모든 캐릭터 WebP의 alpha 채널을 확인했다. 생성 도구 호출은 배경 1회이며 캐릭터는 실제 모델 출력이다.
미검증: 실제 청감/BGM 음량, 배포 환경, 실제 두 사용자 경기 회귀, 모든 화면 크기의 외형.
최초 로비 작업에서는 1대1 자동 매칭을 구현하지 않았으나 아래 후속 작업에서 연결했다. 외부 배포·커밋은 수행하지 않았다.

## 메뉴 슬라이드

`SlidingLobbyMenu.tsx`에서 전환 시 이전 화면의 비활성 시각 복사본만 잠시 보여준다.
앞으로 이동하면 메인/이전 메뉴는 왼쪽으로 빠지고 새 메뉴는 오른쪽에서 들어온다.
뒤로가기는 반대 방향이며 시간은 340ms이다. 배경·캐릭터·고정 화살표는 움직이지 않는다.
이전 화면의 React 구독/Room/로딩 요청을 다시 실행하지 않으며 복사본은 포커스·클릭 대상에서 제외한다.
연속 클릭 시 이전 애니메이션을 취소하고 최신 화면으로 전환한다. reduced-motion 설정에서는 즉시 변경한다.
이번 후속 수정은 웹 타입 검사만 수행했다. 수동으로 네 메뉴 진입, 뒤로가기, 빠른 연속 전환과 스크롤을 확인한다.

중복된 온라인 플레이 중간 메뉴를 제거했다. 방 찾기/만들기/코드 참가의 뒤로가기는 메인 로비로 직접 돌아온다. 빠른 플레이 연결 중에는 검색/취소 안내만 표시하며 기존 연결 취소 규약은 유지한다.

## 농구공 재질

게임·캐릭터 미리보기·로비 에셋은 `apps/web/game/createBasketball.ts`를 공유한다.
기존 3개의 돌출된 Torus 고리를 없애고, 주황색 가죽/검은 곡선 패널/미세 요철을
절차적 색상·노멀 텍스처로 한 번 생성해 Scene 안에서 재사용한다. 외부 사진 텍스처는 사용하지 않는다.
`BALL_STYLE`에서 선 폭, 요철 크기/강도, 반사와 구체 분할을 조절한다.
게임 공 반경은 기존 COURT.ballRadius이며 물리·소유권·득점 로직은 바꾸지 않는다.
로비 캐릭터 이미지 6종도 다시 출력했다. 이번 외형 수정은 타입 검사와 에셋 출력만 확인했으며
실제 플레이 중 조명/회전/근접 질감은 사용자가 확인한다.

## 떠 있는 패널과 버튼 반응

로비 코트 배경을 메뉴 뒤까지 확장하고 메뉴에 바깥 여백·18px 모서리·반투명 남색 배경·
12px 배경 흐림·그림자를 적용했다. 빠른 플레이의 연두색은 따뜻한 주황색으로 변경했다.
정밀 포인터의 호버에서 버튼은 2.5% 확대되고 2px 떠오르며 배경/테두리가 강조된다.
눌림과 키보드 포커스를 구분하고 reduced-motion에서는 확대/이동을 생략한다.
작은 화면에서도 반투명 카드와 텍스트 대비를 유지한다. 이번 후속 변경은 CSS와 문서만 수정했으며
브라우저 확인은 미수행이다. 호버·클릭·메뉴 슬라이드·좁은 화면의 여백을 수동 확인한다.

## 빠른 매칭 상태 창

1대1과 2대2 빠른 플레이는 전용 모달에서 검색 스피너와
“방을 찾고 있습니다…”를 보여준다. 실제 연결 성공을 확인한 뒤에만 “방을 찾았습니다!”로 바꾸고
700ms 동안 안내한 다음 기존 경기 준비 화면으로 이동한다. 실패를 성공으로 표시하지 않는다.
검색/발견 안내 중 취소, 첫 화면 복귀, 화면 해제는 기존 연결 세대를 무효화하며
이미 연결된 대기 Room과 안내 타이머도 정리한다. 키보드 포커스는 모달에 두고 Esc로 취소할 수 있다.
이번 후속 수정은 웹 타입 검사만 실행했다. 검색 중 취소·발견 안내 중 취소·정상 입장·연결 실패는 수동 확인한다.
1대1도 동일한 서버 좌석 예약 경로를 사용한다. 요청 mode는 duel/teamDuel만 허용하고, 목록 선택과 별개로 같은 모드의 공개 WAITING 방만 선택한다. 빈 방이 없으면 해당 모드 방을 생성한다. 중복 요청 식별에 mode를 포함하며 1대1 정원은 기존 서버 규칙(2명)을 따른다. 이전 클라이언트의 mode 없는 요청은 2대2로 처리한다.

1대1 연결 후속 검증: 웹/서버 타입 검사 통과. quickPlay 서버 집중 테스트 4개 통과(1대1 동시 2석 예약, 세 번째 별도 방, 모드·비공개 분리, 동일 요청 ID의 모드 변경 거부 포함). 브라우저·전체 빌드는 이번 후속 작업에서 실행하지 않았다. 수동으로 두 창에서 1대1 선택 → 빠른 플레이 → 검색/발견 안내 → 같은 방 입장과 검색/발견 중 취소를 확인한다.
