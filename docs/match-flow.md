# 반코트 1대1 MVP — 2026-11-06

## 기존 기능과 이번 범위

기존에는 자유 연습의 점수 귀속·공 소유권·스틸·블록·아웃 교대가 있었다.
준비, 카운트다운, 승리 조건, 최종 결과, 상호 재경기 동의는 없었다.
이 상태 흐름만 기존 OnlineWorld/Colyseus 방에 추가했다. 물리·조작·이동 예측과
ACK 재생·보간·실린더 충돌·오프라인 모드는 같은 코드를 사용한다.
npm/package-lock과 설치된 Colyseus 0.17 버전은 바꾸지 않았다.

방 만들기의 `1대1 경기` / `자유 연습`을 선택한다. 서버가 생성 옵션을 검증하며
입장자가 다른 옵션을 보내도 모드는 바뀌지 않는다. 기본 생성 선택은 1대1이다.
Room ID 참가 방식은 유지하며, 경기 대기 화면에서는 초대 코드로 표시한다.

## MVP 규칙

- 11점 이상 먼저 도달하면 승리. 2점 차 조건, 경기/공격 제한시간, 파울·자유투는 없다.
- **기존 자유 연습은 실제 코드상 1점/2점**이었다. 이를 변경하지 않고, 1대1만 같은
  릴리스 위치·외곽선 판정(`pointsAt`)에 +1해 안쪽 2점/밖 3점으로 계산한다.
- 첫 경기 첫 공격자는 서버의 무작위 선택이다. 재경기는 이전 경기 첫 공격자의 상대부터 시작한다.
- 득점하면 실점한 사람이 다음 공격. 공격자는 (0,0,-1.5), 수비자는 (0,0,0)에 배치한다.
  기본 실린더 중심 거리는 1.5m로 겹치지 않는다. 공은 공격자 드리블 위치에 배치한다.
- 공격 교대는 서버 기준 1초 준비 후 허용한다. 승리 점수에 도달하면 교대 없이 결과를 확정한다.
- 수비자가 리바운드·스틸·패스 캐치 등으로 공을 소유하면 새 공격 측으로 기록하고 클리어를 요구한다.
  골대 중심과 공 소유자 root의 수평 거리가 `CFG.arc=6.75m` 이상이면 완료한다.
  기존 화면의 외곽선과 같은 설정이다. 같은 공격자의 리바운드, 비행 중 일시적 무소유,
  블록 자체는 공격 측을 새로 정하지 않는다.
- 슛 릴리스 시 matchId/shotId/shooterId/점수/클리어 자격을 고정한다.
  클리어 전에 던진 슛은 이후 조건이 바뀌어도 득점하지 않는다. 패스는 득점하지 않는다.
- 아웃은 기존 마지막 터치의 상대 규칙으로 공을 주고, 1대1에서는 시작 위치 재배치와 준비 구간을 적용한다.
  기존 아웃 판정 경계 자체는 바꾸지 않았다.

## 서버 상태와 입력 경계

`WAITING → COUNTDOWN(3초) → PLAYING → FINISHED`를 서버 시뮬레이션 시간으로 관리한다.
PLAYING 안의 setupEnd가 공격 교대 준비 구간이다. 브라우저 문구나 타이머가 경기를 시작하지 않는다.
COUNTDOWN/교대 준비/종료 동안 이동·게임 행동·공 물리 판정을 실행하지 않는다.

준비·취소·재경기는 별도 matchIntent 메시지이며 현재 참가자, 경기 세대와 상태를 검증한다.
중복 요청은 카운트다운을 연장하거나 경기를 두 번 만들지 않는다. 두 사람 동의가 있어야 재경기를 시작한다.
경기 점수와 자유 연습 통계는 별도이며, 결과에는 닉네임·최종 점수·승자를 복사해 퇴장 후에도 유지한다.

게임 입력은 기존 seq/moveSeq/ACK에 matchId와 epoch를 추가한다. 이전 세대/준비 구간의 입력은
실행하지 않고 확인 경계를 진행시킨다. 경기를 재시작해도 seq/ACK를 0으로 되돌리지 않는다.
명시적인 상태 전환 때 큐·버튼·충전·Gather·예약 릴리스·수비·스크린을 정리한다.
클라이언트도 epoch가 바뀌면 미확인 입력·보간 표시를 재기준화하고, 이전 버튼 release를 버린다.
로컬 카메라 yaw/pitch는 계속 로컬 입력을 따른다. 일시적 프레임 지연 취소 정책은 추가하지 않았다.
새 경기에서는 과거 오디오/네트 표시 예약도 정리하며 사건 sequence와 shotId는 역행하지 않는다.

## 참가·퇴장

- WAITING/COUNTDOWN 퇴장: 준비 해제, 카운트다운 취소, WAITING 복귀 후 자리 재사용 가능.
- PLAYING 퇴장: ABORTED. 정상 승리와 구분하고 공/득점 처리를 멈춘다.
- FINISHED 퇴장: 확정 결과 유지, 재경기 동의 대기 해제.
- 진행 중/종료/중단 방에는 새 사용자를 투입하지 않는다. Room 인증과 world.join에서 검사한다.
- 마지막 퇴장 시 기존 Colyseus 자동 dispose가 시뮬레이션 구독과 방을 정리한다.
  별도 경기 setTimeout이나 재접속 유예 타이머는 만들지 않았다.

## 두 사람 실행 순서

1. 같은 코드의 웹·게임 서버를 실행한다(`npm run dev:online` 또는 각각 `dev:next`, `dev:server`).
   다른 장치라면 기존 GAME_SERVER_HOST/NEXT_PUBLIC_GAME_SERVER_URL 설정이 필요하다.
2. A는 닉네임을 넣고 `1대1 경기`로 방을 만든다. 화면의 초대 코드를 B에게 전달한다.
3. B는 같은 웹에서 닉네임과 Room ID를 넣고 참가한다. 양쪽의 준비 상태를 확인하고 `준비`를 누른다.
4. 서버 카운트다운이 끝나면 각자 `경기 입장 / 계속하기`를 클릭한다. 이 사용자 클릭에서
   Pointer Lock과 오디오 활성화를 요청한다. 경기 시작만으로 잠금 성공을 가정하지 않는다.
5. 득점 후 재배치와 공격 교대, 스틸/리바운드 후 클리어 안내를 확인한다. Esc 메뉴에서 복귀/나가기를 선택한다.
6. 11점 도달 시 양쪽 결과를 비교한다. 한 명만 재경기를 누르면 대기하며, 둘 다 누르면
   점수 초기화·첫 공격 교대·새 3초 카운트다운으로 이어진다.
7. 플레이 중 한쪽이 나가면 상대의 중단 표시와 `나가기 · 혼자 연습`을 확인한다.

  독립 Chrome headless 두 창에서 준비 → 시작 → 실제 마우스 슛 릴리스 → 득점 → 공격 교대
  → 양쪽 결과 → 양쪽 재경기 → 첫 공격 교대 → 퇴장 중단 → 오프라인 복귀를 확인했다.
  결과 점수는 각 화면에서 좌우가 반대이며 같은 플레이어 점수가 일치했다. 브라우저 예외 0개.
  **득점 경로와 종료 검증을 짧게 하기 위해 테스트 방의 공을 림 위로 옮기고 두 번째 공격자의
  점수를 8점으로 설정했다. 실제 11점 경기를 조작만으로 완주한 검증은 아니다.**

배포 서버·외부 두 장치·장시간 지연 환경·수동 플레이 체감과 음질은 미검증이다.
외부 배포는 하지 않았다. 테스트 도구는 새 로컬 방만 만들고 자체 Chrome/HTTP/Colyseus를 정리한다.

## 제한과 후속 첫 화면 정리 요구

로그인·DB·Redis·랜덤 매칭·영구 전적·랭크·광장·2대2·파울·자유투・골텐딩·슛클록·제한시간은 없다.
네트워크 끊김 유예/재접속 복원도 없다. 자유 연습에는 경기 규칙을 강제하지 않는다.

**현재 첫 화면이 복잡하다는 사용자 피드백을 후속 요구로 보존한다.**
첫 화면에 음소거/전체 음량/오디오 기술 제어/카메라 흔들림/개발 시나리오/재시도/
개발 진단을 계속 늘어놓지 않는다. 음량·음소거·카메라 흔들림은 설정,
시나리오·재시도는 연습 모드 내부, 출처는 설정/크레딧, 진단은 개발 모드로 옮길 예정이다.
향후 첫 화면의 주요 선택은 빠른 경기, 친구와 플레이, 혼자 연습, 게스트 닉네임/로그인,
작은 설정 버튼과 배경의 작은 온라인 광장이다. 이번에는 첫 화면 전체/광장을 새로 만들지 않았고,
새 경기 패널에는 설정 항목을 추가하지 않았다. 기존 첫 화면 설정 정리는 후속 작업이다.
이 후속 요구는 이후 [첫 화면·메뉴 작업](menu-flow.md)에서 구현했다.
