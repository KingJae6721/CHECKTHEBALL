# 플레이어 선택 색상

설정의 **내 캐릭터 색상**에서 청록/주황/파랑/보라/노랑/차콜을 선택한다.
좌석·입장 순서·내 화면/상대 화면에 따른 고정색이 아니다. 같은 색을 골라도 강제로 바꾸지 않는다.
유니폼·반바지·헤드밴드 색, 점수판 표시와 득점 효과에 선택 색을 사용한다.
기존 1인칭 가시성과 피부색, 골격/모션/충돌은 유지한다. 오프라인 더미 색상은 기존값을 유지한다.

- 선택지/팔레트/검증: `packages/protocol/src/playerColor.ts`.
- 로컬 저장 키: `check-the-ball.character-color.v1` (기존 닉네임/오디오 키와 분리).
- 저장 데이터 누락/손상은 청록 기본값. 저장소 차단 시 현재 메모리 선택으로 동작한다.
- 생성/코드/목록 참가 모두 기존 연결 옵션에 `color` ID를 전달한다.
- 서버 actor의 `color`를 스냅샷으로 전달하고 ID에 따라 해당 캐릭터에 적용한다.
- 방 안의 변경은 `playerColor` 메시지에 색상 ID만 전송한다. 서버는 연결된 자기 actor만 갱신하고
  허용 목록 밖의 값/타인 ID가 들어간 객체를 무시한다. 다른 사용자 선택은 덮어쓰지 않는다.
- 재경기 때 프로필 색을 유지하고 재참가 때 저장된 선택값을 다시 보낸다.
- 색상 갱신 메시지는 이동 입력/슛 판정과 독립적이다. 설정 화면을 열 때의 입력 취소는 기존 정책이다.
- 렌더러는 색이 바뀔 때만 팔레트를 갱신한다. 색별 Geometry를 Scene 안에서 캐시하며 공유 재질을
  다른 플레이어 색으로 덮어쓰지 않는다. 메시·Skeleton·손 소켓은 재생성하지 않는다.

웹과 게임 서버를 함께 갱신해야 온라인 선택 색상이 동기화된다. 외부 배포는 수행하지 않았다.

검증: 관련 8개 테스트(실제 SDK 두 클라이언트의 서로 다른 선택/실시간 변경/같은 색 선택/재참가,
타인 색 위조 무효, 스킨 Geometry 공유/복원 및 기존 골격 동작 포함), 웹/서버 타입 검사.
전체 테스트/프로덕션 빌드와 브라우저에서의 직접 색 선택 조작은 이번 변경에서 실행하지 않았다.

사용자 확인: 두 창에서 각각 다른 색 선택 → 같은 방 입장 → 상대 유니폼과 점수판 색 비교 →
설정에서 변경하고 양쪽 반영 확인 → 새로고침 후 선택 복원 → 재경기/재참가 확인.
